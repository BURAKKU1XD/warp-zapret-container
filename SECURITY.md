# Безопасность

Проект экспериментальный; гарантированного срока исправлений и поддержки
старых версий нет. Не используйте контейнер как публичный открытый прокси.

## Границы доверия

- HTTP/SOCKS не требуют аутентификации. Сохраняйте публикацию на `127.0.0.1`.
  Другие контейнеры в доступной Docker-сети также могут достучаться до
  слушателей, привязанных к `0.0.0.0` внутри контейнера.
- В Kubernetes используйте внутренний ClusterIP и NetworkPolicy для выбранных
  клиентов. Chart включает такую политику, но она требует поддержки CNI;
  другие политики могут расширять доступ. Не публикуйте Service наружу.
  Chart монтирует только hostPath `/dev/net/tun`, без hostNetwork/privileged.
- Контейнер работает от root с `NET_ADMIN`, `NET_RAW` и `/dev/net/tun`.
  Не используйте `--privileged` или host networking без отдельной необходимости.
- `CONFIG` — исполняемый Bash-код. Подключайте только доверенные конфиги,
  предпочтительно read-only. Это не безопасный формат для недоверенного ввода.
- WARP state volume содержит приватную регистрацию. Не публикуйте его,
  резервные копии, `.env`, `docker inspect` и сырые логи. Startup/failure
  вывод WARP также может включать идентификаторы и данные регистрации.
- В Git и Docker context исключаются локальные секреты и диагностика.
  `.gitignore` действует на неотслеживаемые файлы, `.dockerignore` — на
  содержимое контекста сборки. Опубликованная история Git сохраняется.

## Сообщение об уязвимости

Для приватного сообщения об уязвимости используйте GitHub Private
vulnerability reporting в разделе Security, когда этот канал доступен.
Иначе запросите приватный контакт через issue. Детали эксплуатации,
ключи и логи передаются по приватному каналу.

Для обычных сетевых сбоев достаточно указать версию образа/WARP/nfqws,
стратегию, ОС/Docker, код ошибки и очищенный результат healthcheck.
Сначала удалите из диагностики IP пользователя, registration IDs, ключи,
токены, лицензию и персональные пути.
